# Slice 02 — Armada-compatible NIP-17 cryptographic core

## Agent brief

Implement only this slice after Slice 01 is green. Read `docs/IMPLEMENTATION_PLAN.md`, especially the NIP-17/NIP-59 contract. Keep crypto independent of OpenClaw runtime and relay networking. Write the negative tests before production code.

## Functional outcome

Given an Armada-compatible gift-wrapped DM addressed to the bot, the library returns an authenticated plaintext `kind:14` message and its real sender pubkey. Given reply text and a recipient pubkey, it creates a fresh gift-wrapped response that an independent recipient key can decrypt.

This outcome is demonstrated entirely offline with fixtures and disposable keys.

## Dependencies

- Slice 01 package, identity parsing, and test infrastructure.

## In scope

- Implement `src/nip17.ts` and narrow crypto types.
- Strictly unwrap and validate:
  - signed outer `kind:1059` gift wrap addressed exactly once to the bot;
  - NIP-44 v2 decryption of a signed `kind:13` seal;
  - seal signature, kind, author, tags, ID, and time constraints;
  - NIP-44 v2 decryption of an unsigned `kind:14` rumor;
  - recomputed rumor ID and exact seal-author/rumor-author equality;
  - one-to-one recipient shape and supported text kind only.
- Construct outbound `kind:14` text rumors, bot-signed seals, and fresh ephemeral-key gift wraps.
- Add reply `p` and triggering-rumor `e` tags.
- Use independent, past-randomized timestamps within the NIP-59 two-day window.
- Return the inner rumor ID as the stable logical message ID.
- Enforce payload and timestamp bounds before expensive or externally visible work.
- Sanitize every crypto error.

## Required tests

- A valid fixture generated by Armada-compatible logic decrypts to the expected sender, recipient, content, timestamp, and rumor ID.
- The outer ephemeral author is never returned as the authenticated sender.
- Reject invalid outer kind, signature, ID, recipient tags, timestamps, and ciphertext.
- Reject malformed seal JSON, wrong seal kind, invalid seal signature/ID, unexpected tags, and seal recipient mismatch.
- Reject malformed rumor JSON, any rumor signature field, wrong recomputed ID, wrong/multiple recipients, unsupported kind, and seal-author/rumor-author mismatch.
- Reject oversized content, stale/future values according to the injected bounds, and malformed NIP-44 payloads.
- Errors and test snapshots contain no `nsec`, plaintext, ciphertext, full event, or contact relationship.
- Two responses with identical logical content have the same intended semantics but independent seals/wraps, different ephemeral keys, and different outer IDs.
- An independent recipient decrypts the response and observes the expected `p` and `e` tags.
- Deterministic clocks/fixtures are used except where randomness itself is under test.

## Implementation notes

- Port and adapt the strict portions of `nostr-community-bot`; do not port its commands, product logic, or runtime dependencies.
- Use audited `nostr-tools` primitives rather than custom secp256k1, Bech32, hashing, or NIP-44 implementations.
- Do not log event bodies. Tests may inspect fixtures directly but production error paths may not.
- Do not implement relay discovery, WebSockets, OpenClaw dispatch, pairing, or self-copy recovery yet.

## Deliverables

- Crypto module, types, fixtures, and complete positive/negative unit suite.
- A test helper that simulates an Armada sender and independently decrypts a bot response.
- Documentation of the authenticated identity result returned to later ingress code.

## Exit gate

- All crypto tests pass without network access.
- Mutation of every signed/hashed/security-sensitive fixture field causes rejection.
- A disposable user key can create a request, the bot core can decrypt it and produce a response, and the user helper can decrypt that response.
- The crypto module imports neither OpenClaw runtime internals nor relay modules.

## Handoff to Slice 03

Expose raw-event-in/verified-rumor-out and logical-message-in/signed-wrap-out interfaces. Keep relay publication and OpenClaw authorization outside this module.
